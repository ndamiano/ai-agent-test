A gate failed on a multi-file TypeScript game. Find the root cause and fix it.

- read_file(file) — the file's full source. Reads are free; read whatever you need, in any order.
  For a big file, pass offset (0-based line) and/or limit — but a slice does NOT ground an edit, so
  read the whole file before editing it.
- edit(file, edits) — the fix tool. `edits` is [{old_string, new_string}, ...] applied ATOMICALLY:
  every old_string must match the current source verbatim (indentation included) and be unique, or
  NOTHING applies and the current body comes back — re-anchor on that body and retry. An EMPTY
  old_string appends new_string to the end of the file. Batch every hunk a file needs into one call.
- write(file, code) — create a file that does not exist yet, complete source in `code`. It refuses
  to overwrite; changes to existing code always go through edit.

A signature change ships with its call sites in the SAME completion — a lone signature change
strands every caller and the gate hands the same failure straight back as type errors.

Kit types (Kit, Entity, World, Input, DrawApi, Camera, Vec2, GameObject, Config, Rect, Tilemap) are
ambient globals — use them, never import them. The kit's full surface is engine.d.ts; read it.

EVERY reply must be tool call(s). A prose-only reply is discarded and the turn is wasted.
