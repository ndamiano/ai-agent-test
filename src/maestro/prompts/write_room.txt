A ROOM is a background the player clicks around in. You give it a `bg` and a list of HOTSPOTS.
Each hotspot is a clickable rectangle plus a `logic` body that runs when it is clicked.

USE THE GIVEN IDS — never invent or rename:
- `bg` = an EXACT background id from asset_manifest.backgrounds.
- An item you grant/check = an EXACT id from the items list (rooms.items / asset_manifest.items).
- A `jump` target = a room id in CURRENT ROOMS (or the room you create THIS call), or `win`.
- A `call` target (talk) = a dialogue node id from node_scripts.
- Dialogue speakers = an EXACT character id from premise.characters; narration is a bare line.

HOTSPOT RECT — [x, y, width, height] in pixels on a 1280x720 frame:
- Keep every box fully inside 0..1280 / 0..720, width and height > 0.
- Don't overlap boxes; space them over the things in the scene they name.

HOTSPOT LOGIC — a few lines of Ren'Py that MUST end by `return` (back to the room) or
`jump room_x` (leave it). Write just the body (no `label` line); compose these verbs:
- EXAMINE: a bare quoted line, then return.
        "The desk drawer is locked. A brass keyhole, recently oiled."
        return
- TAKE an item: guard so it is taken once, then return.
        $ if "item_key" not in inventory: inventory.append("item_key")
        "You pocket the key."
        return
- USE an item (a puzzle): gate on the inventory, set a flag or move, else say why not.
        if "item_key" in inventory:
            $ door_unlocked = True
            "The key turns. The door is open."
        else:
            "It's locked. You need a key."
        return
- TALK to a character: call their dialogue node, then return.
        call talk_warden
        return
- MOVE to another room:
        jump room_hall
- WIN once the goal is satisfiable:
        jump win

MAKE THE ROOM REAL — 2+ hotspots, each doing something. A room the player can enter but not
leave is a dead end: at least one hotspot must `jump` to another room (or `win`).
