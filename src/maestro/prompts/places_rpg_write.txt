You author the WALKABLE WORLD of a tile-based RPG. The player moves an AVATAR around a grid of tiles
with WASD; certain tiles move them to another zone or start a fight. The characters, assets, items,
and the combat encounters are SETTLED — under LOCKED COMPONENTS. {{include:tool_call_rule}}
Build one zone per write_place(place_id, content) call, in the place shape shown under "Required
component shapes" below. Declare the global scaffold ONCE with
set_places_meta(goal={"type":"flag","id":"<win_flag>"}, flags=[...], start_place="<first zone id>",
start_spawn={"cell":{"x":<col>,"y":<row>}}).

You PAINT each zone as a tile map — a grid of chars, one string per row. This is how you actually
design the space: lay ground and paths where the player walks, and obstacles (trees, walls, water) to
shape it into rooms, corridors, and clearings. A bordered empty box is a FAILURE — carve real terrain.

A ZONE needs:
- "kind": "world_map", "town", or "interior" (NOT "room" — that is point-and-click).
- "tiles": { "legend": {<char>: {"role": ..., "theme": ...}}, "rows": ["...", "..."] }
  - "rows": one string per grid row, top to bottom. Every row MUST be the same length. The grid size
    is just the shape of rows — make it as big as the zone needs (e.g. 8-14 wide, 6-10 tall).
  - "legend": maps each tile char to {"role": "open"|"blocked", "theme": "<what it looks like>"}.
    role is the ONLY thing that affects play: open = the avatar can walk on it, blocked = a wall it
    cannot enter. theme is free flavour that drives the tile's look (e.g. "frozen stream", "ash
    pine", "temple stone"). Use theme to make each zone LOOK like its place.
  - These default chars need NO legend entry (use them freely): "." ground, "," path, "#" wall,
    "T" tree, "~" water, "%" rock. Add a legend entry only for a NEW char or to re-theme a default.
- "interactables": each at a {"cell":{"x","y"}} TILE — x = column (0..width-1), y = row
  (0..height-1), counting from the TOP-LEFT. It must sit on an OPEN tile.

THE ACTION verbs (one per interactable):
- examine: {"type": "examine", "text": "what the player sees"}
- take:    {"type": "take", "item": "<item id>", "text": "optional"}
- talk:    {"type": "talk", "node": "<dialogue node id in `nodes`>"}
- move:    {"type": "move", "target": "<zone id>", "spawn": {"cell": {"x","y"}}, "requires": {<cond>}}
           // spawn = the arrival TILE in the destination zone, REQUIRED. requires optional (a lock).
- use:     {"type": "use",
            "clauses": [{"requires": {<cond>}, "outcome": {"text": "...", "effects": [{<eff>}]}}],
            "fallback": {"text": "why it didn't work"}}
- win:     {"type": "win", "requires": {<cond>}}                            // requires optional
- start_combat: {"type": "start_combat", "encounter": "<encounter id in `combat`>"}
           // step onto this tile to enter that fight; it resolves back to the zone.

TRIGGERING: walking ONTO a move/start_combat tile fires it; talk/examine/take/use/win fire when the
player presses E while standing on that tile.

LAYOUT RULES (the build will reject a map that breaks these):
- rows must be rectangular (all the same length); every char must be a default or in the legend.
- Put every interactable and every spawn on an OPEN tile, INSIDE the grid.
- Never put two interactables on the same tile.
- Every interactable must be WALKABLE-reachable from the spawn over open tiles — do not wall it off.
  Leave clear paths between the spawn, the exits, and every interactable.
- Make it a ROUND TRIP: besides its forward exit, give each zone a `move` BACK toward where the
  player came from, so no zone is a one-way strand.

USE THE GIVEN IDS — item ∈ declared items; talk node ∈ `nodes`; move target ∈ a zone id (or one you
create); start_combat encounter ∈ `combat`; never invent or rename. Walkable maps render their tiles
and need no background image.
