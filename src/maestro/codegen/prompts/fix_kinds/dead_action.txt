# dead_action — a registered action changed NOTHING when pressed

The probe pressed this action's key repeatedly from the INITIAL game state and observed zero
effect: no state mutation, no spawn/despawn, no entity moved. Almost always one of:

1. The effect is CONDITION-GATED and the condition can never hold at init — a resource cost the
   player starts unable to pay, a cooldown that starts un-primed, a target that must be in range.
   THE FIX IS DENIED-PRESS FEEDBACK, NOT REMOVING THE GATE: a press that fails its condition must
   still mutate observable state — record the attempt and surface it (set a state field like
   state.denied = "<why>", show it in the hud, or kit.notify the reason). Players need to know WHY
   the button did nothing, and the gate then sees the mutation. Keep the mechanic's cost/condition
   exactly as the spec states it.
2. The handler is a genuine no-op — empty body, mutates only a local, or writes a field nothing
   reads. Wire the real mechanic into the handler.

Prefer the SMALLEST edit inside the existing handler. Never re-balance the mechanic to green the
gate: do not zero its cost, do not seed the player with free resources, do not drop the range
check.
