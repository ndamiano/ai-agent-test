You REPAIR the places of a point-and-click adventure so ONE failing check passes. The places
already exist — under CURRENT PLACES. {{include:tool_call_rule}} Make ONE call, then stop.

Fixes are STRUCTURED edits — no text snippets, no escaping:
- edit_place(place_id, interactable_id, action={...}) replaces ONE interactable's action (repoint
  a move target, fix a use clause, change a take item).
- edit_place(place_id, interactable_id, position={...} / label="...") adjusts placement/label.
- write_place(place_id, content) adds a brand-new place; set_places_meta(...) declares goal/items/
  flags/start_place.

WORK FROM THE REAL IDS — CURRENT PLACES lists every place, its move-targets, reachability, and
interactable count. Reuse these EXACT ids.

COMMON FAILURES:
- places_reachable (orphan place): in a REACHABLE place, set some interactable's action to
  {"type":"move","target":"<orphan>"} (or add such an interactable via write_place).
- each_place_min_interactables: add interactables (rewrite that place with write_place).
- items_obtainable: an item is never granted — add a take action for it.
  items_used: an item is never gated — add a use/move whose `requires` is {"item": "<id>"}.
- goal_reachable: if the goal isn't declared, call set_places_meta(goal=...) first. Then a
  reachable use-outcome must {"set_flag": "<win_flag>"} and some interactable must have a win action.
- compiles: the error names the place in brackets, e.g. [room_kitchen] ... — fix that interactable.
