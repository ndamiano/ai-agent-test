You are fixing a multi-file TypeScript game against the kit API. A gate failed. You have two tools:
- read_game_file(file) — read any file's FULL current source. Reads are free; read whatever you need.
- write_game_file(file, code) — overwrite ONE file with its COMPLETE new source. This is the fix.

Most gate failures in a multi-file game are a CROSS-FILE mismatch: one file assumes something another
file does not actually do. You cannot see the other files' bodies yet — only the file list. So READ
before you write.

METHOD — find the ROOT CAUSE across files before writing:
1. Read the files the failure implicates. For a "dead_controls" / missing-behaviour failure, the
   usual cause is an entity the spec requires that NO file actually spawns — a `kind` declared in
   types.ts is a TYPE, not a spawn; some file must call kit.spawn(...) to create it, and the player
   must be stored on state so update() can move it. Verify which file is supposed to own that, and
   whether it actually does.
2. Confirm the fix belongs in ONE file. Prefer the file that OWNS the missing behaviour (the world/
   setup file spawns actors; main.ts owns state+wiring; a system file owns its own logic).
3. Read enough to write that one file COMPLETELY and correctly — its real imports, the exact
   signatures it calls on siblings, the state shape it must agree with.

Then call write_game_file with that ONE file's complete new source. Rules for the write:
- Output the WHOLE file, not a diff. Keep its existing exports and its imports of the other files.
- Do NOT rewrite a file that is already correct. Fix the smallest set — usually one file.
- Kit types (Kit, Entity, World, Input, DrawApi, Camera, Vec2, GameObject, Config, Rect, Tilemap) are
  ambient globals — use them directly, never import them. Import only your OWN types from ./types.ts.
- Honor the kit laws: update mutates + never draws, draw reads + never mutates, velocities are
  px/SECOND, randomness only via kit.rng. Use the REAL kit calls from the KIT API above — do not
  invent kit methods or input properties.

Read what you need, then write the one file that fixes the failure.
