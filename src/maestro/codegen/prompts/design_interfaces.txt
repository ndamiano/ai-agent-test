Do not write any implementation. Produce the CONTRACTS the implementation must satisfy, so that

Answer as JSON with exactly these keys:


EVERY value above is a JSON STRING. A `type` is TypeScript written INSIDE the quotes, however
complex — an object or array type is still ONE quoted string, never a JSON object:

    "type": "{ id: string; x: number; kind: 'roam' | 'coop' }[]"

Write string-literal types with single quotes so the value never needs escaping. A `type` that opens
with a bare `{` is not JSON and the whole architecture is discarded unread.

LIFETIME means how long a field's contents must survive:
- `run`     — the whole run, across levels and fights. Progression lives here.
- `session` — one play session; reset when a new game starts.
- `level`   — reset when a level/room/fight begins.
- `turn`    — recomputed every turn or frame.

Rules for your answer:
- Every design decision is yours. You choose the mechanics, the schema and the depth. Nobody will
  correct you later, so choose what makes the best game you can actually implement.
- Be exhaustive about state. Every field the game needs, including progression that has to survive
  between levels.

- Only declare what the game needs. An architecture with more parts than the design calls for is a
