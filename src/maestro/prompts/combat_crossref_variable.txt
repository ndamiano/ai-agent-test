A combat piece reads or writes a VARIABLE that is not declared. The TARGET names the exact site,
e.g. `abilities[focus].requires.var: 'rage' is not a declared variable`.

Fix it by RE-AUTHORING that one slice with its write tool shown under the skeleton below (an
ability → write_ability, a status → set_combat_meta, an encounter condition → write_encounter),
keeping every other field. Two valid fixes:

  - Repoint to a variable the game already declares — set it to an EXACT variable id from the NODES
    below, if one fits the intent.
  - Otherwise DROP the dangling variable: re-author the slice WITHOUT that `requires` gate. A combat
    rule must not depend on a variable nothing declares.

Combat does not declare story variables — it points at an existing one or drops the reference. A var
id is a plain STRING. Fix only the named site; restate the slice's other fields.
